# 沿海台风实况与分级预警网站项目计划书

版本：1.0  
编制日期：2026-09-20  
项目暂定名：沿海台风观察站  
交付阶段：规划立项

## 1. 项目目标

建立面向沿海居民的台风信息网站，让居民在手机上快速了解台风现状、未来移动趋势及所在地的官方预警，并找到对应防御信息。

首页优先回答五个问题：

1. 台风叫什么：中文名、英文名和官方编号。
2. 目前在哪：中心经纬度、官方位置描述及资料时间。
3. 往哪走：当前移动方向、移动速度及官方预测路径。
4. 风力多大：中心附近最大风力和风速，必要时补充中心气压。
5. 与我有什么关系：所选地区的有效预警、发布时间和官方防御指南。

成功标准：试点测试中，至少 8/10 位居民能在 30 秒内找到上述核心信息，并能分辨实况与预报。测试样本应包含中老年用户。

## 2. 服务对象与建设范围

主要用户为沿海常住居民、老人家庭、户外工作人员及临海出行人员。首期覆盖中国大陆沿海地区的数据展示能力，先选择一个具备稳定数据授权的城市试点，再扩展地区。

采用简体中文、移动端优先的响应式网页，不强制注册。用户可手动选择省、市、区县；浏览器定位仅在用户主动操作并同意后使用。默认保存行政区选择，不保存精确位置轨迹。

首期包含台风列表、实况卡片、路径地图、所在地预警、预警详情、官方防御指南及数据状态。多个台风同时存在时可切换，默认优先展示与所选地区有关的官方提示；没有可靠关联依据时按官方编号排列。

后续可增加自愿订阅、历史台风回放、风雨影响图层、风暴潮信息及多语言服务。首期不自行预测登陆时间、不生成疏散路线、不自动发布停工停课结论。

## 3. 核心功能与信息规范

| 模块 | 必须展示 | 展示要求 |
| --- | --- | --- |
| 台风身份 | 官方编号、中文名、英文名、活动状态 | 无名称时使用官方编号，不自行命名 |
| 中心位置 | 纬度、经度、官方位置描述 | 附观测时间；方向与距离有明确参照物 |
| 移动趋势 | 移向、移速、官方趋势描述 | 移速统一 km/h；缺失时写“暂无资料” |
| 强度 | 中心附近最大风力、最大风速 | 风力使用“级”，风速使用 m/s；不得视为用户所在地风力 |
| 台风路径 | 历史实况点、最新中心、预测点 | 实况实线、预报虚线；图例不只靠颜色 |
| 地区预警 | 类型、级别、适用地区、发布单位、时间、状态 | 与用户所选行政区匹配；可查看完整原文 |
| 数据状态 | 资料时间、最近检查时间、来源 | 明确正常、延迟、不可用、历史资料 |

页面时间统一显示北京时间（UTC+8），后台使用带时区的标准时间。预报点同时显示起报时间与对应有效时间，禁止把预报位置放入“当前中心位置”。

地图点击路径点后展示该时刻的位置、风力和资料性质。只显示数据源实际提供的预报时效；若提供不确定性范围，应展示并解释。不能把一条预测线解释为全部影响范围。

距用户所选城市的中心距离可作为辅助信息，必须标明参照位置及“直线距离”；距离不能用于生成预警等级或到达倒计时。

## 4. 分级预警设计

### 4.1 信息发布与传播原则

网站展示气象部门正式发布的预警，保存并提供完整原文、发布单位、发布时间、适用区域和原始链接。中国气象局相关办法规定预警信号实行统一发布，并对传播来源、内容完整性和时效提出要求。[来源 1]

预警等级直接取自授权数据源，不依据台风中心风力或距城市远近自行判定。地方可能使用补充等级或不同标准，界面应保留来源的等级名称和图标，例如地方使用白色信号时不能强行映射为蓝色。[来源 1]

### 4.2 四级信号说明

下表是中国气象局附件中的台风信号标准摘要，用于帮助理解；涉及受热带气旋影响的沿海或陆地风力，具体适用以当地发布为准。[来源 1]

| 级别 | 标准摘要 | 页面呈现 |
| --- | --- | --- |
| 蓝色 | 24 小时内可能或已受影响，平均风力 ≥6 级或阵风 ≥8 级，并可能持续 | 蓝色图标、等级文字、官方指南入口 |
| 黄色 | 24 小时内可能或已受影响，平均风力 ≥8 级或阵风 ≥10 级，并可能持续 | 黄色图标、等级文字、官方指南入口 |
| 橙色 | 12 小时内可能或已受影响，平均风力 ≥10 级或阵风 ≥12 级，并可能持续 | 橙色图标、等级文字、官方指南入口 |
| 红色 | 6 小时内可能或已受影响，平均风力 ≥12 级或阵风 ≥14 级，并可能持续 | 红色图标、等级文字、官方指南入口 |

蓝、黄、橙、红都在首页显著展示。较高级别强化视觉优先级；不采用持续闪烁或自动播放警报声。颜色之外同时显示名称、图标与文本，兼顾色觉障碍和老年用户。

### 4.3 地区匹配与生命周期

按数据源的行政区代码或覆盖范围匹配，不能只做城市名称的字符串匹配。省、市、区县多条预警并存时，保留各自发布单位及覆盖范围；首页突出适用于所选地点的最高等级，并提供全部有效预警列表。

支持新发布、更新、升级、降级、解除和到期状态。根据来源的唯一标识、版本及替代关系去重，保留审计记录。不把推测的有效时长当成官方解除；没有有效期或解除信息时，依据供应方业务规则核验，无法核验则标为“状态待确认”。

“未查询到有效预警”“预警数据暂不可用”“预警已解除”使用不同文案。没有预警不等于没有危险。暴雨、风暴潮等相关灾害以后作为独立信息类型展示，不混成一个台风级别。

防御建议以发布单位原文为主。停课、停航、转移安置等行动信息只有在接入当地主管部门公告后展示，并附来源和适用范围。

## 5. 页面与用户流程

首页顺序：地区选择 → 所在地预警 → 台风实况四项摘要 → 路径地图 → 官方防御指南 → 数据来源与更新状态。

用户进入网站后先手动选择地区，也可主动定位；无定位权限时全部核心功能仍可使用。选择台风后阅读实况卡片，在地图中查看历史与预测路径，再打开所在地区预警了解完整内容。

页面结构示意：

```text
沿海台风观察站                 [选择地区]
所在地预警：等级 / 适用地区 / 发布单位 / 发布时间
[查看完整预警与防御指南]

台风名称与编号                [切换台风]
位置：经纬度 + 官方位置描述
移动：方向 + 速度
风力：中心附近最大风力 + 风速
资料时间 / 数据来源 / 数据状态

路径地图：实况 ━━━  预报 ┄┄┄
[查看路径文字列表]

官方指南 / 来源链接 / 数据说明
```

地图加载失败时，文字卡片和路径时间列表继续可用。没有活动台风时显示空状态与当地其他已接入预警；历史台风必须带“历史资料”标签。演示数据全程标注“演示”，与生产数据隔离。

## 6. 数据来源与接入方案

台风资料优先评估中央气象台及具备合法授权的气象数据服务，预警优先接入气象主管机构提供或授权的实时信息。中央气象台台风网作为官方产品参考；国家政务服务平台提供气象灾害预警查询入口。[来源 2、3]

公开网页能够访问不代表允许商业使用或自动采集。中央气象台页面包含数据使用授权提示，正式开发前须确认再分发许可、接口文档、更新频率、区域覆盖、限流和费用；本计划没有假定任何已获授权的免费 API。[来源 4]

数据接入交付物包括供应商确认记录、字段映射、样例报文、授权范围、刷新约定和故障联系人。若短期无法取得可靠预警接口，可上线明确标注的演示原型或官方查询入口，不能把模拟预警作为实况上线。

建议建立三类核心记录：

| 记录 | 主要字段 |
| --- | --- |
| 台风 | 官方编号、名称、状态、数据来源 |
| 实况／预报点 | 台风编号、资料类型、观测或起报时间、有效时间、坐标、风力、风速、移向、移速、来源 |
| 预警 | 来源标识、版本、灾种、原始级别、覆盖区域、发布单位、发布时间、有效期、生命周期状态、原文、原始链接 |

所有记录附接收时间，原始报文留档。关键字段缺失时不补造数据；不把不同时间的风力和位置拼成一条实况。多源冲突时保留来源差异，按预设权威来源优先级展示。

刷新频率按授权接口约定配置。服务端定期检查并缓存，浏览器从本站接口读取，不能让每位访客直接请求上游。预警与实况分别配置超时阈值；默认可按约定更新周期的两倍判定延迟，最终由数据服务约定确认。

## 7. 技术实现与运行保障

采用响应式前端、服务端数据接口、数据接入任务、数据库和缓存组成的结构。地图服务需核验中国大陆地区使用条件、底图授权及坐标体系，避免台风点位与行政区偏移。具体框架和云平台在实施阶段按团队能力、授权服务和预算确定。

接入链路为：授权数据源 → 报文校验与归档 → 标准化及区域匹配 → 数据库存储／缓存 → 网站文字卡片和地图。

API 密钥仅存服务端；前端请求限流，展示文本做安全转义。页面默认不要求姓名、手机号等信息。后续如增加订阅，另行设计同意、退订、通知权限与数据删除流程。

运行监控覆盖上游请求失败率、资料时效、预警处理延迟和网站可用率。上游异常时保留最后一次资料作为标明时间的历史参考，停止将未核实预警显示为有效；附官方查询入口。

项目目标：在约定测试环境下移动端核心文字信息于 3 秒内可见；网站月度可用率目标 99.9%，上游资料中断另行记录；上游成功返回后，95% 的预警在 60 秒内完成本站处理与展示。此目标不代表官方发布至本站的总延迟。

## 8. 实施排期与人员

建议安排一个 6 周的试点周期，以数据授权和接口可用为启动前提。授权采购等待时间单列，不计入确定性开发排期。

| 阶段 | 主要工作 | 可交付结果 |
| --- | --- | --- |
| 第 1 周 | 确定试点地区、数据授权、需求及数据字典 | 需求确认、来源清单、字段规范 |
| 第 2 周 | 手机页面原型、预警状态与易读性测试 | 可评审原型、文案与交互说明 |
| 第 3 周 | 接入实况、预报与地图 | 实况及路径功能测试版 |
| 第 4 周 | 地区匹配、分级预警、完整原文及生命周期 | 预警模块与回放测试结果 |
| 第 5 周 | 弱网、故障、无障碍与安全验证 | 验收记录、监控及运维手册 |
| 第 6 周 | 居民试用、修正问题、灰度上线 | 试点版本、上线检查与复盘 |

建议投入：产品／设计 0.5–1 人，前端 1 人，后端与数据 1 人，测试 0.5 人；气象业务顾问参与标准和文案审阅。预计约 18–21 人周，属于规划估算。

预算采用“人周 × 团队单价 + 数据授权费 + 地图授权费 + 云资源和监控费 + 后续通知费”的方式编制，另留约 15% 项目预备金。具体金额以供应商报价及访问量评估为准。

## 9. 验收标准

- 随机抽取至少 20 个历史资料时刻，台风名称、位置、移动方向与速度、中心风力及资料时间和来源一致；缺失字段正确显示。
- 实况点、预测点、起报时间和有效时间清楚区分，地图与文字列表信息一致。
- 使用固定报文覆盖蓝、黄、橙、红及地方扩展信号，等级与原文不被修改。
- 完成发布、升级、降级、解除、重复、乱序和过期预警测试；旧版本不能覆盖新版本。
- 用省、市、区县覆盖关系验证预警匹配；不将其他地区预警误显示为本地预警。
- 模拟上游中断、响应成功但资料未更新、地图失败、定位拒绝与无活动台风，状态均可正确辨识。
- 在窄屏手机、键盘操作和屏幕阅读器下完成主要流程；核心信息不依赖颜色或地图。
- 使用包含中老年人的居民样本完成 30 秒信息查找测试，并记录结果。
- 生产上线前确认数据再分发授权、来源署名、监控、回滚方案及运行责任人。

## 10. 主要风险与应对

| 风险 | 应对措施 |
| --- | --- |
| 授权或接口进度延迟 | 第一周优先解决；演示数据与生产环境严格区分 |
| 地方预警标准不同 | 保留原始级别与完整原文，逐地区核验 |
| 资料延迟被误认为最新 | 同时显示资料时间和检查时间，触发延迟提示 |
| 访问高峰或地图故障 | 缓存、文字降级、容量测试和故障演练 |
| 用户误把路径线当成影响边界 | 明示预报性质，提供官方风雨影响入口 |
| 紧急通知未送达 | 后续推送不承诺必达，页面持续展示官方查询渠道 |

实施前待确定：试点城市、数据服务方及授权范围、项目预算上限、团队配置、域名及托管平台。以上项目不影响当前计划书和仓库建立。
